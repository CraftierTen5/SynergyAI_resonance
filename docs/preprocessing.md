# Preprocessing and policy resolution

`app.main:app` mounts the multipart `POST /preprocess` router along with `/`, `/health`, and `/ready`. An embedding host may use `create_preprocess_router` and inject a `policy_lookup(assignment_id)` callback returning authoritative records with `policy` (`NO_AI`, `PROCESS_DISCLOSURE`, or `FULL_INTEGRATION`), optional `version`, and optional `required_conditions`. No database or assignment repository exists in this source snapshot, so unresolved policy uses `YELLOW` guided assistance.

The route accepts student text and up to five image files. When an assignment ID is provided, it resolves policy before calling Gemini: RED is rejected and YELLOW requires the request's `disclosure_acknowledged=true` plus returns configured conditions. Missing, ambiguous, out-of-scope, or conflicting policy resolves to YELLOW while retaining its reason code. Acknowledgment is not durably persisted because no user/account storage exists. The service checks PNG, JPEG, and WebP signatures, preserves original student text, returns normalized text and extracted image content separately, and marks empty OCR as partial success. Responses include requested language, translation/extraction statuses, and provenance. Provider output is parsed and type checked. Provider configuration, authentication, throttling, timeout, invalid response, and outage errors return safe errors; originals are not logged.

The current source does not contain assignment persistence, authenticated assignment authorization, a public tutoring endpoint, or durable preprocessing decision audit storage. Candidate policy evidence remains review-only; final interpretation uses an authoritative record when available and otherwise falls back to YELLOW. The future classifier integration point is after this route returns `processed_text`, `policy.policy_flag`, and relevant assignment context. Qwen is intentionally not invoked.
